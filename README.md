# Итоговый вопрос

Процессор обычно загружает данные целыми блоками — кэш-линиями, равными 64 байта.
Последовательный доступ: при последовательном доступе загрузка одной кэш-линии может сразу
дать процессору несколько следующих элементов. Когда процессор запросит следующий элемент, он уже будет лежать в быстром кэше.

# Контрольные вопросы

1. Чтобы не ждать медленную оперативную память.
2. Кэш быстрый. Хранит часто используемые данные ближе к процессору. Оперативная память - медленная, находится отдельно.
3. Минимальный блок данных, который процессор загружает из памяти за один раз.
4. При последовательном доступе все данные из загруженной кэш-линии используются. 
5. Точные значения зависят от процессора, оперативной памяти, версии
.NET и других процессов Windows.

# Итоговый вывод

Эксперимент показал, что время выполнения программы напрямую зависит от шага доступа к элементам массива. При увеличении шага (например, с 1 до 16) время доступа заметно возрастает, так как процессор начинает чаще обращаться к медленной оперативной памяти. Это связано с тем, что при последовательном доступе (шаг 1) процессор эффективно использует кэш-линии, загружая сразу блок соседних данных и получая кэш-попадания. При большом шаге из загруженной линии используется лишь один элемент, а остальные данные выбрасываются впустую, вызывая кэш-промахи. Таким образом, кэш-память играет ключевую роль в производительности: чем лучше программа использует пространственную локальность, тем быстрее она работает.
